# 职级对标

在中国科技公司之间跳槽，或在中国和国际公司之间流动时，第一个问题往往是"这个职级到底相当于什么？"。各公司的职级命名、级数和要求都不同，网上流传的对照表也常常过时。这个技能根据用户手上的职级资料和 offer 信息做对比，解释每个职级在实际工作中通常意味着什么，并把差距转化为向招聘方提问的问题。

除非另有要求，用简体中文写。

## 产出内容

- **对比表**：涉及的职级及每个对应关系的依据
- **职级画像**：每个职级的典型范围、独立程度、带人情况，以及晋升门槛
- **Offer 判断**：给出的职级是否与用户的经验和当前职级相符
- **向 HR 或面试官确认的问题**，弄清这个职级在该公司的实际含义

## 所需输入

如未提供，请询问：
- **当前公司和职级**，以及工作年限
- **目标公司和给出的或预期的职级**
- **岗位序列**：研发、产品、设计、数据、运营
- **能提供的职级文件**、职级说明或 offer 信
- **要做什么决定**：接受、谈判，还是设定晋升目标

## 方法

1. **以用户的文件为准。** 职级体系会调整；把公司自己的说明作为依据，并明确说出来。
2. **按范围对标，而不是按数字。** 比较每个职级要负责的东西：一个任务、一个模块、一个系统、一条产品线、一块业务。数字相同的两个职级，范围可能差整整一级。
3. **谨慎使用公开参考。** 广为流传的例子包括阿里的 P 序列（P6 通常被描述为资深个人贡献者，P7 为负责重要领域的专家）和字节的两段式职级（如 2-1、2-2）。把这些作为常见说法和近似参考，并提醒用户向对方公司确认。
4. **用证据检查 offer。** 用用户的实际范围（团队规模、负责的系统、影响）对照目标职级的要求，而不只看头衔。
5. **把差距变成问题。** "这个职级在团队里通常负责什么范围？"、"下一级的晋升标准是什么？通常需要多久？"、"这个职级对应的薪酬带宽是多少？"、"团队里同级别的人做什么？"

## 输出格式

### 职级对比
| 公司 | 职级 | 典型负责范围 | 独立程度 | 带人情况 | 依据（文件 / 公开信息 / 推测） |

### 职级画像
每个职级：一句话定位、典型职责、晋升到下一级的关键门槛。

### Offer 判断
- 你的实际范围对应：[职级区间]
- 对方给出的职级：[职级] → 偏低 / 合理 / 偏高，理由：[...]

### 建议向 HR / 面试官确认的问题
1. ...

### 说明
职级对标是近似的。各公司职级体系会调整，同一职级在不同部门的实际范围也可能不同，请以对方公司的正式说明为准。

## 质量检查

- [ ] 每个对应关系都写明了依据：用户的文件、公开信息或推测
- [ ] 按范围和要求对比职级，而不只按数字
- [ ] 公开参考标注为近似
- [ ] Offer 判断给出了与用户实际范围相关的理由
- [ ] 至少包含四个具体的、可以问招聘方的问题
- [ ] 除非用户提供，不写任何薪资数字

## 反模式

- **把网上的表格当事实。** 职级体系会重组，旧的对照表会误导人。
- **按头衔对标。** "高级"或"专家"在不同公司含义不同。
- **忽略晋升门槛。** 一个容易拿到却很难升上去的职级，和起点一样重要。
- **引用传闻中的薪酬带宽。** 去问对方公司。

## 示例触发语

- “阿里 P7 跳槽到字节，大概对应什么职级？”
- “这个 offer 给了 2-1，我现在是 P6，合理吗？”
- “我要去新加坡，帮我把腾讯的职级和谷歌的职级对比一下。”
- “帮我对标一下职级，下周要谈 offer。”
