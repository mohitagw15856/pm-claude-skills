# RICE 优先级排序

对一组功能或计划项采用一致、基于标准的 RICE 打分，得出客观的优先级排序。

## 从大脑读取 / 写入大脑

如果存在 [`professional-brain`](../../../skills/professional-brain/SKILL.md)（`brain/`），以它为依据，而不是重新询问你已经知道的：

- **先读：** `knowledge/strategy.md`（让排序服务于方向）、作为 `entities/` 的各项，以及关于影响的 `hypotheses/`。运行 `python3 ../professional-brain/scripts/brain_query.py ./brain "<initiative theme>"`，并保留每条事实的来源标注：影响估计通常是 `[hunch]`，不是 `[data]`。
- **📥 向大脑提议：** 产出后，提议把排序决策记入 `decisions/`，把覆盖面和影响的估计记为按证据强度标注的 `hypotheses/`。先展示，得到同意后用 `../professional-brain/scripts/brain_write.py … --commit` 写入（只追加，默认试运行）。

## 所需输入

如未提供，请向用户询问：
- **要打分的计划项或功能清单**（名称和简短描述）
- **覆盖面估计**（每季度受影响的用户数，最好来自数据分析）
- **影响估计**（使用下面的标准刻度）
- **工作量估计**（人月，最好来自工程团队）
- **季度或规划周期**

## RICE 定义（按你的情况调整）
- **覆盖面（Reach）：** 每季度受影响的用户数（尽量使用真实的日活或月活数据）
- **影响（Impact）：** 对主要指标的作用，刻度：3 = 巨大，2 = 高，1 = 中，0.5 = 低，0.25 = 极小
- **信心（Confidence）：** 我们对覆盖面和影响的估计有多确定？100% = 高，80% = 中，50% = 低
- **工作量（Effort）：** 所有职能合计需要的人月

## RICE 公式
RICE 分数 = （覆盖面 × 影响 × 信心）/ 工作量

## 程序辅助

这个技能附带一个只用标准库的 Python 脚本，用来计算和排序 RICE 分数，让算术保持一致，速赢和登月的标注按规则而不是凭感觉。收集齐 R、I、C、E 之后把计划项交给它。

```bash
# 从 JSON 文件（信心可以写 0.8 或 80）
python3 scripts/rice_calculator.py initiatives.json

# 或者从 CSV，表头：name,reach,impact,confidence,effort
python3 scripts/rice_calculator.py initiatives.csv --format csv

# 或者通过管道输入
echo '[{"name":"Onboarding","reach":5000,"impact":2,"confidence":0.8,"effort":3}]' \
  | python3 scripts/rice_calculator.py -
```

它输出带计算分数的排序表，并自动标注**速赢**（分数高、相对工作量低）、**登月**（影响高、工作量高）和**低信心**（不超过 50%）的项目。把计算出的排序作为起点，然后执行下面的验证步骤：绝不在没有检查背后估计的情况下接受一个出人意料的第一名。

## 延伸材料

- **`references/estimate-calibration.md`**：如何为四个估计找锚点（覆盖面来源、附"留给什么情况"示例的影响刻度、基于证据的信心、跨职能的工作量），以及对完成的排序要做的交叉检查。质疑用户输入时使用。
- **`templates/scoring-worksheet.md`**：可填写的工作表，证据列强制每个分数写出来源。团队想一起打分而不是生成排序时提供。

## 它在流程中的位置：主线上的打分

产品决策主线的第三步：**`/assumption-mapper` → `/prd-template` → `rice-prioritisation` → `/roadmap-narrative`**。它从每个计划项的 PRD 接收**成功指标**：RICE 的 *Impact* 是对*那个*有基线的数字的预计变化，而不是重新猜一个；它把**带分数的排序计划项**交给 `/roadmap-narrative` 按主题分组。四个 RICE 术语统一定义在 [`docs/craft/product-decisions.md`](../../../docs/craft/product-decisions.md)；那里的*信心*是诚实阀门，这个技能成败全看是否用好它。

## 循环

当估计是为了得到想要的排序而编出来时，RICE 就失效了。这个循环的任务是让每个分数保持诚实；第二阶段就是做这件事的地方。

1. **为每个计划项收集四个估计。** 覆盖面（每个周期的真实人数）、影响（对 PRD 成功指标的幅度）、信心（0 到 1）、工作量（人月）。上游 PRD 有指标时，从中取影响。
   **完成标准：** 每个计划项四项齐全，并且每项都标注了来源。
2. **审问信心：防止操纵的阶段。** 每个估计的信心必须反映*证据*，而不是热情：没有数据的大胆影响只能拿低信心，分数会自我修正。质疑薄弱的输入，并说出什么数据能提高它们（具体方法见 [estimate-calibration](../../../skills/rice-prioritisation/references/estimate-calibration.md)）。
   **完成标准：** 没有哪个 [hunch] 估计挂着高信心，每个估计的负责人都愿意当面为每个数字辩护。
3. **打分、排序，并压力测试排名第一的项目。** 计算 RICE、排序，标注*速赢*（分数高、工作量低）和*登月*（影响高、工作量高），记录依赖。然后交叉检查：如果第一名让团队意外，很可能某个估计被夸大了。RICE 是工具，不是裁决。
   **完成标准：** 排序已计算，第一名经受住了一次诚实的追问："这感觉对吗？如果不对，哪个估计在撒谎？"
4. **交接。** 把排序表（带分数和依赖）交给 `/roadmap-narrative`，让它按主题分组，而不是重新推导优先级。
   **完成标准：** `/roadmap-narrative` 无需重新打分就能给这些项目分主题。

## 评分量表（0 到 40）

交付前给这个技能的任何产出打分；32 分以上才算可以交付。

| 维度 | 0 | 5 | 10 |
|---|---|---|---|
| 估计可信度 | 整数猜测配 100% 信心；工作量只由产品经理估计 | 覆盖面基于数据分析，但无论证据如何，各项信心都一样 | 每个估计写明来源；没有数据的一律 50% 信心；工作量来自工程团队，文档中说明了这一点 |
| 影响区分度 | 全都打 2 到 3 分：刻度没有产生任何信号 | 在刻度上有一定分布，但没有定义锚点，分数之间不可比 | 用满整个刻度，每一级都有说明的锚点；"巨大"只留给真正少见的项目 |
| 排序审问 | 直接接受原始排序结果作为裁决 | 标注了速赢和登月，但出人意料的排名和依赖没有检查 | 调查了出人意料的第一名，找出被夸大的估计或为其辩护；在依赖会改变顺序的地方做了记录 |
| 可执行的顺序 | 只有打了分的表，没有建议 | 有表和前 5 名，但没有理由，也没有数据缺口的后续 | 建议顺序附每项理由，速赢项与大项目并行安排，并写明能让下一轮更准的数据缺口 |

## 质量检查

- [ ] 每个计划项四个 RICE 要素都有估计（哪怕粗略）
- [ ] 没有数据支撑的一律 50% 信心（而不是默认 100%）
- [ ] 明确指出速赢项和登月项
- [ ] 记录了影响顺序的依赖
- [ ] 出人意料的排名在接受之前经过调查

## 反模式

- [ ] 不要对缺少数据支撑的估计默认 100% 信心：这会抬高分数、误导规划
- [ ] 不要把 RICE 分数当作最终决定：让团队意外的排名必须先调查再接受
- [ ] 不要省略工程团队的工作量估计：只由产品经理估计的工作量常常过于乐观，会扭曲结果
- [ ] 不要忘记记录那些即使 RICE 分数相反也会改变顺序的依赖
- [ ] 不要给每个计划项打相同的影响分：如果一切都是"高影响"，框架就产生不了有用的信号
