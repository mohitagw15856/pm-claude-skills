# 指标体系

这个技能为一个产品或业务建立完整的指标体系。它把北极星指标和可行动的先行指标连接起来，让人清楚要跟踪哪些指标、优化哪些指标，以及它们之间的关系。

## 所需输入

如未提供，请向用户询问：
- **产品或业务描述**（一段话就够）
- **商业模式**（SaaS / 平台撮合 / 电商 / 消费类 App / B2B / 其他）
- **阶段**（找到产品市场匹配之前 / 增长 / 规模化 / 成熟）
- **偏好的框架**（如有）：北极星加指标树 / AARRR / HEART / OKR / 自定义
- **本季度的主要目标**（例如提高激活、降低流失、增加收入）

如果没有给出框架偏好，根据阶段和商业模式推荐最合适的。

## 从大脑读取 / 写入大脑

如果存在 [`professional-brain`](../../../skills/professional-brain/SKILL.md)（`brain/`），先用它再提问：

- **先读：** `context.md` 中组织已经认可的指标*定义*（沿用它们，不要悄悄重新定义指标），以及 `knowledge/strategy.md` 中业务在优化什么。
- **之后写：** 把指标树和定义保存到 `knowledge/`，把设定目标的决策记入 `decisions/`，都标注来源，这样基于 `[hunch]` 的目标不会被当作已承诺的目标。

## 输出结构

### 1. 框架推荐（如未指定）

用 2 到 3 句话解释为什么在他们的情况下推荐这个框架。

---

### 2. 北极星指标

**[指标名称]：** [定义：到底衡量什么、怎么衡量]

**为什么这是这个业务合适的北极星：**
[2 到 3 句。它应反映交付给客户的价值，而不只是收入或活跃。说明它捕捉了什么行为，以及为什么最大化它与长期业务健康相关。]

**如何衡量：** [公式或数据来源]
**当前基线：** [留作 [ADD BASELINE] 由用户填写]
**目标：** [留作 [ADD TARGET] 由用户填写]

---

### 3. 指标树

展示支撑指标如何汇总到北极星。用层级格式：

```
[北极星指标]
├── [驱动因素 1：例如 获客]
│   ├── [二级指标：例如 每周自然注册数]
│   └── [二级指标：例如 各渠道付费获客成本]
├── [驱动因素 2：例如 激活]
│   ├── [二级指标：例如 7 天内完成引导的用户占比]
│   └── [二级指标：例如 到达首次价值动作的时间]
└── [驱动因素 3：例如 留存]
    ├── [二级指标：例如 第 30 天留存率]
    └── [二级指标：例如 功能使用深度]
```

每个二级指标写明：
- **定义：** [到底衡量什么]
- **为什么重要：** [它如何与北极星相连]
- **先行还是滞后？** [先行 = 有预测性 / 滞后 = 结果]
- **如何衡量：** [数据来源或计算方法]

---

### 4. 反向指标

[2 到 3 个需要盯住的指标，防止用损害业务的方式优化北极星。例如："如果优化注册数，就要盯住垃圾账号比例。如果优化活跃度，就要盯住客服工单量。"]

---

### 5. 看板建议

建议三层看板结构：
- **高管视图（每周）：** [3 到 5 个指标，只看结果]
- **团队视图（每天）：** [7 到 10 个指标，先行指标加产出]
- **诊断视图（按需）：** [出问题时用来下钻的指标]

---

### 6. 指标健康检查问题

[团队在每周指标回顾中应该问的 5 个问题，把数字变成洞察。例如："激活率在提升而留存持平？这说明是引导质量问题，而不是产品市场匹配问题。"]

这个技能附带支持文件，可用时请使用：

- **`references/metric-tree-craft.md`**：驱动决策（而不是装饰看板）的指标树。在产出时应用它；它包含上面方法摘要压缩掉的校准和判断。

## 评分量表（0 到 40）

交付前给这个技能的任何产出打分；32 分以上才算可以交付。

| 维度 | 0 | 5 | 10 |
|---|---|---|---|
| 北极星有效性 | 北极星是业务活动（GMV、收入、浏览量）或虚荣的数量 | 北极星指向客户价值，但定义没有处理边界情况（取消、纠纷、退款） | 北极星计算的是真正交付给客户的价值，定义中解决了边界情况，并写明了被否决的备选及理由 |
| 指标树的因果完整性 | 二级指标是一份与北极星没有因果联系的扁平 KPI 清单；驱动因素重叠或全属一类 | 驱动因素各不相同，但有些二级指标只是与北极星相关而非驱动它，或先行 / 滞后标签靠猜 | 3 到 4 个不同的驱动因素，推动任何二级指标都可能推动北极星，先行 / 滞后标签诚实，包括承认目标指标本身是滞后的 |
| 定义精确度 | 指标只有名字，没有公式、数据来源或时间窗口 | 大多数指标有公式，但至少有一个两位合理的分析师会算出不同结果 | 每个指标都写明公式、来源表或事件以及时间窗口，精确到两位分析师能算出同一个数 |
| 防操纵 | 没有反向指标；默认每个指标都会被善意优化 | 列出了笼统的反向指标，但没有与它所保护的具体指标配对 | 每个可被优化的指标都配一个反向指标，并写明它能发现的具体反常操作（先接单后取消、靠折扣买来的留存、虚假供给） |

## 质量检查

- [ ] 北极星反映客户价值，而不只是业务活动
- [ ] 指标树有 3 到 4 个不同的驱动因素（不全是一类）
- [ ] 每个二级指标都标注了先行或滞后
- [ ] 包含防止反常激励的反向指标
- [ ] 看板层级按产品阶段定制
- [ ] 所有指标定义都没有歧义（公式或清楚的描述）

## 反模式

- [ ] 不要把衡量业务活动（收入、浏览量）而不是交付给客户的价值的指标设为北极星：这会造成与产品质量错位的激励
- [ ] 不要在不写公式或数据来源的情况下定义指标：含糊的指标会被不同的人用不同方法衡量
- [ ] 不要跳过反向指标：没有护栏地优化任何单一指标，最终都会产生反常激励
- [ ] 不要在团队每日视图中放超过 4 到 5 个指标：有 20 个指标的看板就是没人看的看板
- [ ] 不要把所有指标都标为"先行"：诚实区分哪些是滞后的结果指标，哪些真正能预测未来结果
