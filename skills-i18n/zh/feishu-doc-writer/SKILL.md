# 飞书文档

飞书（海外版叫 Lark）是很多中国团队写方案、复盘和会议纪要的地方，而飞书读者习惯快速浏览：先看摘要高亮块，再通过目录跳转，最后在任务清单里找自己的名字。这个技能把笔记或草稿整理成适合这种阅读方式的文档，输出的 Markdown 粘贴或导入飞书后能被干净地转换。

除非要求英文或繁体中文，用简体中文写。

## 产出内容

- **文档正文**：可直接粘贴的 Markdown，包含一级标题、二级和三级标题、表格、任务清单
- **顶部结论高亮块**：结论、需要的决策、截止时间
- **任务清单**：带 `@负责人` 占位和日期，可转换为飞书任务
- **分享消息**：两三行，用于发到飞书群，写明需要谁做什么决定

## 所需输入

如未提供，请询问：
- **材料**：笔记、草稿、会议记录或要点
- **文档类型**：方案、会议纪要、复盘、需求文档、周报或其他
- **读者**：本团队、跨团队还是管理层
- **行动项的负责人和日期**，或同意先用 `@待定` 占位
- **团队模板**：如果空间里已有模板，优先按模板来

## 方法

1. **结论先行。** 高亮块写明结论、需要的一个决策和截止时间。只读到这里的人也应该能正确行动。
2. **标题适配目录。** 飞书根据标题生成目录，所以每个二级标题都要说明内容（"二、方案对比"，而不是"二、其他"）。最多两级。
3. **比较用表格，步骤用列表。** Markdown 表格粘贴到飞书效果好；避免合并单元格，转换后会丢失。
4. **行动项写成任务清单。** 格式为 `- [ ] 事项 @负责人 截止：MM-DD`。粘贴后读者可以把每一行转成飞书任务并指派。
5. **链接而不是复制。** 其他文档、飞书表格和多维表格用链接引用，不要复制内容，保证只有一个信息源。
6. **纯文本替代。** 高亮块、@提及和嵌入卡片在 Markdown 中不存在。用清楚的约定标出（`> 💡` 表示高亮块，`@姓名` 表示提及），并在分享说明里列出粘贴后需要转换的内容。

## 输出格式

```markdown
# [文档标题]

> 💡 **结论**：[一句话]
> **需要决策**：[什么事，由谁决定]　**截止**：[日期]

## 一、背景
## 二、[核心内容，按文档类型命名]
| 方案 | 优点 | 缺点 | 成本 | 建议 |
## 三、风险与待定问题
## 四、行动项
- [ ] [事项] @[负责人] 截止：[MM-DD]
## 附：相关文档
- [文档名](链接)
```

然后：
- **粘贴后需要处理**：需要转成高亮块的行、需要替换成真实成员的 @提及、需要转成飞书任务的行
- **群消息**：两三行，写结论、需要的决策和文档链接占位

## 质量检查

- [ ] 第一个块写明了结论、需要的决策和截止时间
- [ ] 每个二级标题都说明了内容，没有"其他"或"补充"
- [ ] 每个行动项都有负责人（或 `@待定`）和日期
- [ ] 表格没有合并单元格，只有一行表头
- [ ] 没有出现用户未提供的事实、数字或人名
- [ ] 粘贴说明列出了导入后需要转换的所有元素

## 反模式

- **没有标题的大段文字。** 飞书读者靠目录导航，没有标题就无从下手。
- **结论放在最后。** 管理层往往只看顶部的块和任务清单。
- **把表格数据复制进文档。** 链接飞书表格，数字才能保持最新。
- **编造负责人。** 不确定就写 `@待定` 并标出来，不要猜。

## 示例触发语

- "帮我把这份会议记录整理成飞书文档。"
- "写一份飞书方案文档，比较这三个方案，领导要做决定。"
- "把这些笔记整理成给跨团队评审用的 Lark 文档。"
- "把复盘内容整理成飞书格式，行动项要能转成任务。"
