# Offer 比较

offer 常常被说成一种感觉（"创业公司上升空间更大"），但最终都会落到带日期的数字上。这个技能计算曲线：未来四年每一年每个 offer 付多少钱、曲线在哪里交叉，以及较弱的 offer 里哪个筹码真的能改变结果。

## 这个技能产出什么

- **薪酬表**：每个 offer 的逐年和累计总额，由脚本计算
- **交叉分析**：哪个 offer 在什么时候领先，以及这个排序依赖于哪个假设
- **风险换算**：把未上市公司的股权如实折算，而不是按面值
- **谈判筹码**：按"每一分开口难度能换来多少钱"排序

## 所需输入

如未提供，请询问：
- **每个 offer：** 基本工资、奖金比例、股权授予价值、归属年数、悬崖月数、归属频率、401(k) 配比（比例和上限）、任何承诺的追加授予
- **用户的时间跨度**：预计待 2 年还是 4 年会改变答案，因为悬崖会改变
- **股权风险看法**：上市公司 RSU 按面值计算；未上市公司股权与用户商定折扣（例如 B 轮前打五到七五折），把折后数字*标明*后传给脚本

## 程序辅助

```bash
python3 scripts/offer_comparison.py offers.json
cat offers.json | python3 scripts/offer_comparison.py - --json
```

输入格式见脚本说明。脚本逐月计算归属（12 个月悬崖到期时释放已累计的一年），按年计算奖金和配比，并报告累计领先者和交叉年份。**它严格按你给的数字计算股权价值**：风险调整是你的输入，清楚可见，绝不是隐藏假设。

## 框架：算术之外的判断

- **悬崖与时间跨度**：预计只待 18 个月，第 4 年的股权就是虚构；按用户实际的时间跨度比较，而不是按授予期限
- **有风险的一块钱不等于工资的一块钱**：绝不把未上市公司的纸面股权与现金一比一比较；如果用户不愿选一个折扣，就展示两三个折扣水平下的比较
- **追加授予是政策，不是承诺**：只有写在纸面上才建模；否则作为表外的潜在收益提及
- **筹码排序：** 基本工资（会叠加到奖金和配比）→ 股权授予 → 签约奖金（一次性，最容易同意）→ 悬崖或入职日期调整

# Offer 比较：[A] 对比 [B]

## 曲线
[脚本输出：逐年、累计、领先者、交叉年份]

## 质量检查

- [ ] 未上市公司的股权折扣是明确的，并经用户同意
- [ ] 按用户说明的时间跨度展示比较，而不只是四年
- [ ] "排序依赖什么"部分展示了翻转后的排序，而不只是点出风险
- [ ] 筹码的金额影响是根据实际 offer 计算的
- [ ] 免责声明出现在成果中

## 反模式

- [ ] 不要把有风险的股权与工资一比一比较：折扣本身就是分析
- [ ] 不要把归属悬崖藏在年平均数里：有悬崖的第一年要单独看
- [ ] 不要把没有写下来的追加授予算作收入
- [ ] 不要在没有说明赢面依赖什么假设的情况下宣布赢家
- [ ] 不要在不附假设的情况下展示模型结果
