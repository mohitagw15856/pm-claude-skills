# OKR 制定

写出有野心、可衡量的 OKR，把产品工作和公司战略连接起来。避免虚荣指标、以产出为导向的关键结果，以及读起来像任务清单的目标。

## 从大脑读取 / 写入大脑

如果存在 [`professional-brain`](../../../skills/professional-brain/SKILL.md)（`brain/`），以它为依据，而不是重新询问你已经知道的：

- **先读：** `context.md`（指标定义）、`knowledge/strategy.md`（产品方向）以及任何未关闭的 `hypotheses/`。运行 `python3 ../professional-brain/scripts/brain_query.py ./brain "<objective theme>"`，并保留每条事实的来源标注：不要把基于 `[hunch]` 的关键结果当成基于 `[data]` 的。
- **📥 向大脑提议：** 产出后，提议把选定的目标和关键结果目标值记为一条 `decisions/` 记录（这个周期的押注），把新的指标定义记入 `knowledge/`，都标注来源。先展示，得到同意后用 `../professional-brain/scripts/brain_write.py … --commit` 写入（只追加，默认试运行）。

## 从简要说明开始工作

你常常会拿到一份简短的说明，缺少一些细节（没有基线、没有确切数字）。**无论如何都要交付一套完整、具体的 OKR**：不要停下来提问，也不要留下 `[target]` 这样的方括号占位符。缺少基线或数字时，根据说明和领域推断一个合理的值，并标注 *（假设，待确认）*。清楚标注的假设基线（例如"激活率 40% *（假设）* → 60%"）永远好过空白，或被当作事实的编造数字。

## 延伸材料

- **`references/bad-okr-gallery.md`**：六个真实的坏 OKR 及诊断和改写（伪装的路线图、无法证伪的目标、压低目标、不可控的关键结果、指标动物园、缺少护栏），最后是一个 5 问诊断。*审查*现有 OKR 时使用：先与样例对照，再写反馈。
- **`templates/okr-worksheet.md`**：可填写的工作表，其列强制执行质量关卡（基线来源、漂移测试、可控性测试、护栏），并附预先约定的季末评分标准。团队想自己起草 OKR 时提供。

## OKR 基础

**目标（Objective）：** 定性、鼓舞人心、有时间限制。回答"我们要去哪里？"
**关键结果（Key Result）：** 定量、具体、可衡量。回答"我们怎么知道已经到了？"

### 好的关键结果的检验
- 期末能否按 0.0 到 1.0 打分？
- 它衡量的是结果而不是产出吗？（"新客户收入增长 30%"，而不是"上线 3 个功能"）
- 有野心但可实现吗？（以 70% 达成为黄金标准）
- 它在团队的控制范围内吗？

## 需要指出并修正的常见 OKR 反模式

| 反模式 | 例子 | 更好的写法 |
|---|---|---|
| 伪装成关键结果的任务 | "上线引导改版" | "新用户激活率从 42% 提升到 65%" |
| 虚荣指标 | "App 下载量达到 1 万" | "新用户 30 天留存达到 40%" |
| 二元关键结果 | "发布 API v2" | "80% 的活跃集成采用 API v2" |
| 关键结果太多 | 每个目标 6 个以上 | 每个目标最多 3 到 4 个 |
| 没有基线 | "提升 NPS" | "NPS 从 32 提升到 50" |

总是指出反模式并给出改写。

## 输出格式

### [季度] OKR：[团队 / 产品领域]

---

**目标 1：[鼓舞人心的定性表述]**

*为什么重要：* [1 到 2 句战略背景]

| # | 关键结果 | 基线 | 目标值 | 衡量方法 |
|---|---|---|---|---|
| KR1 | [可衡量的结果] | [当前状态] | [目标值] | [如何衡量] |
| KR2 | [可衡量的结果] | [当前状态] | [目标值] | [如何衡量] |
| KR3 | [可衡量的结果] | [当前状态] | [目标值] | [如何衡量] |

*负责人：* [姓名 / 角色]
*跟进节奏：* 每周

---

每个目标重复。建议每个团队每季度 2 到 4 个目标。

## 要包含的评分指南

季末给每个关键结果打分：
- 0.7 到 1.0 = 优秀（0.7 是"最佳点"：如果所有关键结果都是 1.0，说明不够有野心）
- 0.4 到 0.6 = 有进展但未达成
- 0.0 到 0.3 = 未达成，需要复盘讨论

## 输入（未提供的可推断，并标注假设）

- OKR 针对的**团队或个人**
- **季度和年份**
- **公司或产品的北极星指标**（OKR 应与之相连；如果没给，推断一个合理的并标注 *（假设）*）
- **本季度最重要的 3 个优先事项或目标**（粗略的笔记就可以）
- **要审查或改进的现有 OKR**（可选）

## 指南

- 把 OKR 与公司或产品的北极星连接起来；如果没给，推断一个合理的并标注 *（假设）*，而不是提问
- 建议每个团队每季度不超过 3 个目标
- 如果用户给的是产出型目标，总是改写为结果
- 包含"健康检查"部分，标出哪些关键结果目前没有基线数据
- 提醒用户：OKR 不是绩效考核，应该有野心到没完成也没关系

## 评分量表（0 到 40）

交付前给这个技能的任何产出打分；32 分以上才算可以交付。

| 维度 | 0 | 5 | 10 |
|---|---|---|---|
| 结果导向 | 关键结果是上线功能的任务清单（"上线 X"、"完成 Y"） | 大多是结果，但有一个或多个关键结果是产出或二元的上线与否 | 每个关键结果都是可按达成程度 0.0 到 1.0 打分的结果指标 |
| 基线与可衡量性 | 没有基线或衡量方法；季末无法打分 | 有目标值，但几个基线缺失或没有来源，也没有健康检查标注 | 每个关键结果都有基线、目标值和衡量方法；缺失的数据在健康检查中标出，并有埋点计划 |
| 野心校准 | 目标是上季度趋势线（压低目标），或没有路径的纯幻想 | 有一定挑战，但没人说得清 0.7 分是什么样子 | 校准到 0.7 达成就是预期中好的季度；压低的提议和登月目标被指出并修正 |
| 战略聚焦与可控 | 与北极星无关；5 个以上目标或关键结果动物园；关键结果依赖其他团队的工作 | 与战略松散相连，但目标过多，或有一个关键结果没通过可控性测试 | 不超过 3 个目标、每个不超过 4 个关键结果，每个目标都明确对应北极星，每个关键结果都在团队控制范围内 |

## 质量检查

- [ ] 每个关键结果都可衡量，有基线和目标值
- [ ] 没有产出型关键结果（没有"上线 X"或"完成 Y"）
- [ ] 每个目标最多 4 个关键结果
- [ ] OKR 与公司或产品的北极星相连
- [ ] 足够有野心，0.7 达成是预期分数

## 反模式

- [ ] 不要接受产出型关键结果：任何写成"上线 X"或"完成 Y"的关键结果都必须改写为有基线和目标值的结果
- [ ] 不要在不问公司或产品北极星的情况下写 OKR：脱离战略背景的 OKR 只是一次定目标练习
- [ ] 不要每个目标写超过 4 个关键结果：太多会分散注意力，季末打分也会含糊
- [ ] 不要用二元关键结果（上线 / 没上线）：每个关键结果都必须能按达成程度 0.0 到 1.0 打分
- [ ] 不要跳过基线健康检查：没有当前基线的 OKR 季末无法客观打分

- “帮我写 OKR。”
- “定一下季度目标。”
- “定义关键结果。”
- “评审现有的 OKR。”
