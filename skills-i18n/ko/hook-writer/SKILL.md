# 훅 작성 스킬

결과의 80%는 훅이 결정한다. 훌륭한 글도 첫 줄이 밋밋하면 묻히고, 평범한 글도 훅이 좋으면 퍼진다. 이 스킬은 상위 크리에이터가 하는 방식으로 훅을 쓴다. 여러 각도에서, 각각 스크롤을 멈추게 설계해서, 맞는 것을 고를 수 있게 한다.

## 간단한 요청만 있을 때

주제만 있거나 완성된 글만 있어도 **훅을 일단 만든다.** 독자와 보상을 추론하고, 안전한 선택지 하나만 내놓지 않는다. 가치는 *폭*에 있다. 지어낸 숫자에는 *(가정. 실제 숫자로 바꿀 것)*이라고 표시한다. 구체적인 숫자는 훅이 먹히는 이유의 일부이기 때문이다.

## 필요한 입력

주어지지 않았다면 다음을 물어본다.
- 훅을 붙일 **주제 / 콘텐츠**
- **플랫폼과 형식** (X, 링크드인, 유튜브 제목, 릴스 콜드 오픈, 이메일 제목)
- **독자**와 **보상** (계속 읽으면 얻는 것)

## 출력 형식

**각도별로 묶은 훅 8~12개**를 제시하고, 각각 한 줄로 *왜 효과가 있는지*와 맞는 형식을 적는다.

- **호기심의 틈**: 독자가 닫고 싶어지는 고리를 연다
- **통념 뒤집기 / 패턴 깨기**: 흔한 믿음에 도전한다
- **구체적인 결과**: 숫자로 된 구체적인 성과
- **이야기 / 사건 한가운데서 시작**: 어떤 순간 속으로 떨어뜨린다
- **걸려 있는 것 / 하지 않을 때의 비용**: 무시하면 잃는 것
- **목록 / 약속**: 분명하고 훑어보기 쉬운 보상
- **질문**: 날카롭고 뻔하지 않은 질문(아껴서 쓴다)

그다음:
- **🏆 상위 3개**: 지정한 플랫폼에 가장 강한 것을 순위와 이유와 함께.
- **훅 해부**: 가장 좋은 훅이 쓰는 *원리*를 한 줄로 적어, 다음에는 사용자가 직접 쓸 수 있게 한다.

각 훅은 플랫폼의 자연스러운 길이를 지킨다(유튜브 제목은 60자 이하, 이메일 제목은 50자 이하, 릴스 콜드 오픈은 2~3초 안에 말할 수 있게).

## 품질 점검

- [ ] 한 문장의 변형이 아니라 정말로 다른 여러 각도가 있다
- [ ] 각 훅이 모호하지 않고 구체적이다(이름, 숫자, 걸려 있는 것)
- [ ] 상위 추천이 플랫폼의 길이와 관행에 맞는다
- [ ] 콘텐츠가 갚지 못할 낚시성 문장이 없다. 훅은 정직해야 한다
- [ ] 훅 해부가 다시 쓸 수 있는 원리를 알려 준다

## 피해야 할 패턴

- "X에 대해 알아야 할 모든 것" (긴장이 전혀 없다)
- 같은 훅을 열 번 고쳐 쓴 것
- 본문이 배신하는 낚시성 문장(장기적으로 신뢰와 도달을 죽인다)
- 플랫폼에 비해 너무 긴 훅(90자짜리 유튜브 제목, 세 줄짜리 "첫 줄")

## 요청 예시

- "훅 써 줘."
- "이 게시물의 첫 문장을 써 줘."
- "이 영상의 콜드 오픈을 써 줘."
- "이 스레드 시작 문장을 더 클릭하고 싶게 만들어 줘."
