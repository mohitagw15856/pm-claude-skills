# 自評

自評是你在別人定義你這一年之前，自己定義它的唯一機會。寫得不好，是一串含糊的活動清單；寫得好，是一段有證據的敘述：把你的工作對應到考核的能力，誠實承認成長方向，併為下一級做鋪墊。這個技能就寫後者，如果你有 [`brag-doc`](../../../skills/brag-doc/SKILL.md)，可以直接從中取材。

## 所需輸入

僅在尚未提供時詢問：

- **你的崗位、職級和評估週期。**
- **成就**：帶影響或資料的成績（或指向你的 brag doc）。
- **考核所依據的能力框架或評分維度**（如有）。
- **成長方向**：做得不夠或想要提升的地方（要誠實；評審者信任自我認知）。
- **下一週期的目標。**

## 輸出格式

### 自評：[姓名]，[崗位]，[週期]

**1. 概述**：3 到 4 句話：這個週期的主線和標題。先寫影響。

**2. 主要成就**：最重要的 3 到 6 項，每項寫成**結果 → 你的貢獻 → 證據 → 體現了哪項能力**。用數字量化；對應到團隊或公司目標。

**3. 優勢**：你最突出體現的 2 到 3 項能力，附證據。

**4. 成長方向**：1 到 3 項，坦白承認：什麼很難、學到了什麼、你在改變什麼。當它具體且不帶防禦時，這一部分會*增加*可信度（不要寫"我工作太拼了"）。

**5. 目標與發展計劃**：下一週期的重點和需要的支援。

**6. 評級理由**（*如需自評打分*）：你給自己的評級和證據，對照評分標準：不誇大，也不假裝謙虛。

## 品質檢查

- [ ] 成就有數字，並對應到能力框架或公司目標
- [ ] 每個說法都有具體證據支撐，而不是形容詞
- [ ] 成長方向真實、具體（不是變相誇自己），並寫了正在怎麼改
- [ ] 敘述有主線，而不只是清單
- [ ] 自評打分（如有）對照評分標準、有證據：站得住，而不是理想化

## 反模式

- [ ] 不要羅列活動：每項成就都對應到結果和能力
- [ ] 不要把優點偽裝成缺點（"太注重細節"）：讀起來像迴避；寫一個真實的成長方向
- [ ] 不要把團隊的成績說成個人的，也不要出於謙虛低估自己的角色：準確說明你的貢獻
- [ ] 不要把自評打分抬到證據支撐不了的程度：在校準時會損失信譽
- [ ] 不要用含糊的最高階：沒有數字，"帶來了顯著影響"毫無意義

## 依據

基於能力的績效評估實踐：對應證據的成就和經過校準的自我評估。
