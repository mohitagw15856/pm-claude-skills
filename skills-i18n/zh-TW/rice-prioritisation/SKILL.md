# RICE 優先順序排序

對一組功能或計劃項採用一致、基於標準的 RICE 打分，得出客觀的優先順序排序。

## 從大腦讀取 / 寫入大腦

如果存在 [`professional-brain`](../../../skills/professional-brain/SKILL.md)（`brain/`），以它為依據，而不是重新詢問你已經知道的：

- **先讀：** `knowledge/strategy.md`（讓排序服務於方向）、作為 `entities/` 的各項，以及關於影響的 `hypotheses/`。執行 `python3 ../professional-brain/scripts/brain_query.py ./brain "<initiative theme>"`，並保留每條事實的來源標註：影響估計通常是 `[hunch]`，不是 `[data]`。
- **📥 向大腦提議：** 產出後，提議把排序決策記入 `decisions/`，把覆蓋面和影響的估計記為按證據強度標註的 `hypotheses/`。先展示，得到同意後用 `../professional-brain/scripts/brain_write.py … --commit` 寫入（只追加，預設試執行）。

## 所需輸入

如未提供，請向使用者詢問：
- **要打分的計劃項或功能清單**（名稱和簡短描述）
- **覆蓋面估計**（每季度受影響的使用者數，最好來自資料分析）
- **影響估計**（使用下面的標準刻度）
- **工作量估計**（人月，最好來自工程團隊）
- **季度或規劃週期**

## RICE 定義（按你的情況調整）
- **覆蓋面（Reach）：** 每季度受影響的使用者數（儘量使用真實的日活或月活資料）
- **影響（Impact）：** 對主要指標的作用，刻度：3 = 巨大，2 = 高，1 = 中，0.5 = 低，0.25 = 極小
- **信心（Confidence）：** 我們對覆蓋面和影響的估計有多確定？100% = 高，80% = 中，50% = 低
- **工作量（Effort）：** 所有職能合計需要的人月

## RICE 公式
RICE 分數 = （覆蓋面 × 影響 × 信心）/ 工作量

## 程式輔助

這個技能附帶一個只用標準庫的 Python 指令碼，用來計算和排序 RICE 分數，讓算術保持一致，速贏和登月的標註按規則而不是憑感覺。收集齊 R、I、C、E 之後把計劃項交給它。

```bash
# 從 JSON 檔案（信心可以寫 0.8 或 80）
python3 scripts/rice_calculator.py initiatives.json

# 或者從 CSV，表頭：name,reach,impact,confidence,effort
python3 scripts/rice_calculator.py initiatives.csv --format csv

# 或者透過管道輸入
echo '[{"name":"Onboarding","reach":5000,"impact":2,"confidence":0.8,"effort":3}]' \
  | python3 scripts/rice_calculator.py -
```

它輸出帶計算分數的排序表，並自動標註**速贏**（分數高、相對工作量低）、**登月**（影響高、工作量高）和**低信心**（不超過 50%）的項目。把計算出的排序作為起點，然後執行下面的驗證步驟：絕不在沒有檢查背後估計的情況下接受一個出人意料的第一名。

## 延伸材料

- **`references/estimate-calibration.md`**：如何為四個估計找錨點（覆蓋面來源、附"留給什麼情況"示例的影響刻度、基於證據的信心、跨職能的工作量），以及對完成的排序要做的交叉檢查。質疑使用者輸入時使用。
- **`templates/scoring-worksheet.md`**：可填寫的工作表，證據列強制每個分數寫出來源。團隊想一起打分而不是生成排序時提供。

## 它在流程中的位置：主線上的打分

產品決策主線的第三步：**`/assumption-mapper` → `/prd-template` → `rice-prioritisation` → `/roadmap-narrative`**。它從每個計劃項的 PRD 接收**成功指標**：RICE 的 *Impact* 是對*那個*有基線的數字的預計變化，而不是重新猜一個；它把**帶分數的排序計劃項**交給 `/roadmap-narrative` 按主題分組。四個 RICE 術語統一定義在 [`docs/craft/product-decisions.md`](../../../docs/craft/product-decisions.md)；那裡的*信心*是誠實閥門，這個技能成敗全看是否用好它。

## 迴圈

當估計是為了得到想要的排序而編出來時，RICE 就失效了。這個迴圈的任務是讓每個分數保持誠實；第二階段就是做這件事的地方。

1. **為每個計劃項收集四個估計。** 覆蓋面（每個週期的真實人數）、影響（對 PRD 成功指標的幅度）、信心（0 到 1）、工作量（人月）。上游 PRD 有指標時，從中取影響。
   **完成標準：** 每個計劃項四項齊全，並且每項都標註了來源。
2. **審問信心：防止操縱的階段。** 每個估計的信心必須反映*證據*，而不是熱情：沒有資料的大膽影響只能拿低信心，分數會自我修正。質疑薄弱的輸入，並說出什麼資料能提高它們（具體方法見 [estimate-calibration](../../../skills/rice-prioritisation/references/estimate-calibration.md)）。
   **完成標準：** 沒有哪個 [hunch] 估計掛著高信心，每個估計的負責人都願意當面為每個數字辯護。
3. **打分、排序，並壓力測試排名第一的項目。** 計算 RICE、排序，標註*速贏*（分數高、工作量低）和*登月*（影響高、工作量高），記錄依賴。然後交叉檢查：如果第一名讓團隊意外，很可能某個估計被誇大了。RICE 是工具，不是裁決。
   **完成標準：** 排序已計算，第一名經受住了一次誠實的追問："這感覺對嗎？如果不對，哪個估計在撒謊？"
4. **交接。** 把排序表（帶分數和依賴）交給 `/roadmap-narrative`，讓它按主題分組，而不是重新推導優先順序。
   **完成標準：** `/roadmap-narrative` 無需重新打分就能給這些項目分主題。

## 評分量表（0 到 40）

交付前給這個技能的任何產出打分；32 分以上才算可以交付。

| 維度 | 0 | 5 | 10 |
|---|---|---|---|
| 估計可信度 | 整數猜測配 100% 信心；工作量只由產品經理估計 | 覆蓋面基於資料分析，但無論證據如何，各項信心都一樣 | 每個估計寫明來源；沒有資料的一律 50% 信心；工作量來自工程團隊，文件中說明了這一點 |
| 影響區分度 | 全都打 2 到 3 分：刻度沒有產生任何訊號 | 在刻度上有一定分佈，但沒有定義錨點，分數之間不可比 | 用滿整個刻度，每一級都有說明的錨點；"巨大"只留給真正少見的項目 |
| 排序審問 | 直接接受原始排序結果作為裁決 | 標註了速贏和登月，但出人意料的排名和依賴沒有檢查 | 調查了出人意料的第一名，找出被誇大的估計或為其辯護；在依賴會改變順序的地方做了記錄 |
| 可執行的順序 | 只有打了分的表，沒有建議 | 有表和前 5 名，但沒有理由，也沒有資料缺口的後續 | 建議順序附每項理由，速贏項與大專案並行安排，並寫明能讓下一輪更準的資料缺口 |

## 品質檢查

- [ ] 每個計劃項四個 RICE 要素都有估計（哪怕粗略）
- [ ] 沒有資料支撐的一律 50% 信心（而不是預設 100%）
- [ ] 明確指出速贏項和登月項
- [ ] 記錄了影響順序的依賴
- [ ] 出人意料的排名在接受之前經過調查

## 反模式

- [ ] 不要對缺少資料支撐的估計預設 100% 信心：這會抬高分數、誤導規劃
- [ ] 不要把 RICE 分數當作最終決定：讓團隊意外的排名必須先調查再接受
- [ ] 不要省略工程團隊的工作量估計：只由產品經理估計的工作量常常過於樂觀，會扭曲結果
- [ ] 不要忘記記錄那些即使 RICE 分數相反也會改變順序的依賴
- [ ] 不要給每個計劃項打相同的影響分：如果一切都是"高影響"，框架就產生不了有用的訊號
