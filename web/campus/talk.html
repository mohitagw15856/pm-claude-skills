问题

直接说"帮我写周报"会怎样？

常见结果一份流水账：周一开会，周二改需求，周三对接……没有数字，没有风险，没有下周计划。
上级想看的本周完成（带数据）· 关键数据 · 问题与风险 · 下周计划 · 需要的支持，外加一句能发群里的摘要。

差别不在模型，在于有没有告诉它"这件事应该怎么做"。

0:03 让一位同学念左边，大家会笑。强调：模型知道很多，但不知道你们学院、你们公司对"好"的标准。

定义

Agent Skill = 把"怎么做"写成一份 Markdown

  • 什么时候用：触发语，比如"帮我写周报""写开题报告"
  • 需要什么输入：缺了就先问你，不瞎编
  • 按什么方法做：资深的人才知道的判断
  • 产出什么格式：交付物长什么样
  • 交付前检查什么：可以逐条判断的质量标准
0:08 类比：技能就像实验室里师兄写给新生的操作手册。手册不会让你变聪明，但会让你少犯新手错误。

长这样

一个技能文件

---
name: cn-weekly-report
description: "Write a Chinese workplace weekly report (周报)...
  Use when asked 帮我写周报, 写月报, 整理本周工作..."
---
# 中文周报
## 所需输入      本周笔记、目标或 OKR、上周计划、读者
## 框架          本周完成 / 关键数据 / 问题与风险 / 下周计划 / 需要的支持
## 质量检查      每条成果有数字？风险有应对？计划有日期？

学术诚信

AI 能帮你什么，不能替你做什么

可以理清结构、检查逻辑、整理笔记、找出你没想到的追问、检查引用格式、模拟面试
不可以把 AI 写的内容当作自己的作业或论文提交；编造数据和参考文献；违反课程和学校关于 AI 使用的规定

先看清楚你的课程和学校怎么规定。不确定时，问老师，并在作业里说明你怎么用了 AI。

0:34 这一页一定要讲，语气认真。技能里的质量检查也会要求"不出现用户没有提供的数字"，但最终责任在自己。

动手

写你自己的第一个技能：5 步

  1. 选一件你每周都做、好坏标准明确的事
  2. 写下老手的 3 到 6 个步骤，和新手最常犯的 3 个错误
  3. 新建 skills/<技能名>/SKILL.md，填好描述和触发语
  4. 交给同学：只看技能文件，不问你，看结果是否达标
  5. 跑结构检查：node scripts/skillcheck.mjs
0:36 可以提到 make-me-a-skill 和 writing-great-skills 这两个技能，它们会帮你写技能。详细步骤在开源小课第四、五课。

好技能的三个检验

  • 质量检查能不能逐条判断通过与否？"写得清楚"不能，"每个行动项都有负责人和日期"能
  • 方法里有没有只有老手才知道的判断？没有的话，它只是一个模板
  • 会不会编造事实？加上"没有出现用户未提供的数字"
