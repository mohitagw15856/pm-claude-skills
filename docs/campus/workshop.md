# 社团工作坊：两小时，从安装到写出第一个技能

[校园资料包](README.md) · [开源小课](../learn-zh/README.md)

适合计算机协会、产品社、创业社、职业发展协会等社团。参加的同学结束时会：装好技能库，用三个技能完成三件真事，写出并检查自己的第一个技能，知道怎么把它贡献回开源社区。

## 基本信息

- **时长**：120 分钟，中间休息 10 分钟
- **人数**：12 到 30 人，两人一组；每 8 到 10 人配一位助教
- **场地**：每人一台电脑，能上网，有投影
- **前置要求**：会打开命令行；装好 Node.js 18 以上和 Git；有一个能用的 AI 编程工具（Trae、通义灵码、CodeBuddy、Qoder、Cursor 或 Claude Code 任选其一）并能调用模型
- **没有 AI 编程工具的同学**：用浏览器打开魔搭创空间 PM Skills Playground，用魔搭 API-Inference 的免费额度或自己的模型 Key

提前一周把"课前准备"发到群里，开场前十分钟检查所有人的环境，这一步决定了工作坊能不能准时进行。

## 课前准备（发给参加的同学）

```bash
node -v     # 18 或以上
git --version
git clone https://gitee.com/mohitagw/pm-claude-skills.git
```

再准备三样素材（不要包含真实的个人隐私）：一周的随手笔记、一个课程作业或毕设题目、一段你自己的经历（项目、社团或兼职）。

## 流程

| 时间 | 环节 | 做什么 |
|---|---|---|
| 0:00 到 0:10 | 开场 | 用分享会幻灯片第 3、4 页讲清楚"技能是什么"。每组两人，一人操作，一人记录 |
| 0:10 到 0:25 | 安装 | 全场一起跑安装命令，助教巡场解决问题 |
| 0:25 到 0:65 | 用 3 个技能 | 每个技能 12 分钟，最后 4 分钟两组之间交换看结果 |
| 0:65 到 0:75 | 休息 | |
| 0:75 到 1:45 | 写第一个技能 | 选题、写、互测、检查 |
| 1:45 到 2:00 | 分享和下一步 | 三组展示；介绍翻译认领和校园大使 |

### 安装（15 分钟）

```bash
# 换成你用的工具：trae、lingma、codebuddy、qoder、cursor 或 claude
npx --registry=https://registry.npmmirror.com pm-claude-skills add --agent trae

# 不知道用哪个技能时，先问它
npx --registry=https://registry.npmmirror.com pm-claude-skills find "写开题报告"
```

常见问题：`npx` 很慢，确认带了 `--registry` 参数；公司或学校电脑没有权限，换成自己的电脑或用在线试用；通义灵码单个规则超过 10,000 字符会被截断，安装时会列出来，不影响今天的练习。

### 用 3 个技能（40 分钟）

每个练习先**不加技能**问一次，再加技能问一次，两人对比记录差别。

1. **`cn-weekly-report` 周报**：把一周的随手笔记交给它，"帮我写周报"。检查：每条成果有没有数字？风险是否放在前面？下周计划有没有日期？
2. **`cn-thesis-proposal` 开题报告**（理工科也可以换成 `thesis-outline`）：给它一个课程作业或毕设题目。观察：它会先问你缺的信息吗？研究现状里有没有编造的文献？（有的话，这正好是学术诚信的现场案例。）
3. **`graduate-cv` 应届生简历**，接着用 **`cv-honesty-check`** 检查：把你的一段经历写成简历条目，再让它找出面试官会追问、你答不上来的地方。

### 写第一个技能（70 分钟）

1. **选题（10 分钟）**：选一件你每周都做、好坏标准明确的事。好的例子：实验周报、社团活动复盘、组会汇报提纲、课程设计的需求说明。不好的例子："帮我学习"（太大，没有标准）。
2. **写（30 分钟）**：可以先用 **`make-me-a-skill`** 起草，再用 **`writing-great-skills`** 改。新建 `skills/<技能名>/SKILL.md`，包含：描述和触发语（英文写，加上中文说法）、所需输入、三到六步方法、新手最常犯的三个错误、可以逐条判断的质量检查。
3. **互测（15 分钟）**：交给另一组，他们只看技能文件、不问你任何问题，用 AI 完成一次任务。结果没达标的地方，就是技能里没写清楚的地方。
4. **检查（15 分钟）**：

```bash
cd pm-claude-skills
node scripts/skillcheck.mjs          # 结构检查
node scripts/skill-dupes.mjs --check # 和已有技能是否重复
```

重复了也没关系：说明这个需求真实存在，可以改去改进已有的技能。

### 分享和下一步（15 分钟）

- 请三组展示："不加技能"和"加了技能"的结果差在哪里，自己的技能解决了什么问题。
- 想继续：翻译认领板 [`docs/zh/translation-board.md`](../zh/translation-board.md) 上挑一个技能翻译；把今天写的技能提交 PR（用不了 GitHub 就贴到 [Gitee Issue](https://gitee.com/mohitagw/pm-claude-skills/issues)）；想在学校继续办活动，申请[校园大使](ambassadors.md)。

## 给组织者

- **签到表只收昵称和学院**，不需要手机号以外的信息；照片发到公众号前征得同意。
- **模型费用**：工作坊用量不大。魔搭 API-Inference 有免费额度；如果社团统一提供 Key，设好额度上限，结束后立刻作废。
- **学术诚信**：开场就说明，今天的练习用的是虚构或已公开的素材，作业和论文请遵守课程和学校的 AI 使用规定。
- **活动后**：在校园大使申请 Issue 下留言写一句活动总结（人数、提交了几个技能或翻译、同学最常问的问题），帮助我们改进资料。
